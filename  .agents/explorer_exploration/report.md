# VitaShield Codebase Exploration Report

This report compiles findings regarding the VitaShield codebase structure, build system, threat feeds crawling logic, database schema design, browser automation capabilities, and testing scripts.

---

## 1. Directory Structure, Build System, and Configuration

### Directory Mapping
The project is organized as follows:
- **`api/`**: Contains serverless Vercel Node.js API endpoints.
  - `api/cron/crawl.ts`: Crawls open-source threat intelligence feeds and trains the autoencoder.
  - `api/cron/learn.ts`: Performs self-learning loop optimization from real telemetry sessions.
  - `api/model/`: Deployment, retrieval, and training APIs for model parameters.
  - `api/verify.ts` / `api/verify-secure.ts`: Secondary authentication and verify APIs.
- **`dist/`**: The compiled static production build assets.
- **`docs/`**: Documentation files regarding integration and threat intelligence strategy.
- **`public/`**: Static public files, including `widget.js` (telemetry collector) and `public/intel/` (folder storing crawled security documents).
- **`scripts/`**: Offline command-line execution and simulation scripts.
  - `scripts/test-bot.js`: Standalone anti-bot simulation test suite.
  - `scripts/threat_crawler.cjs`: Crawls seed URLs, writes clean documents, and updates `sitemap.xml`.
- **`src/`**: Vite + React 19 Frontend Dashboard application source.
  - `src/components/`: Reusable UI dashboard, admin portal, and rules/ML components.
  - `src/lib/`: Main verification and behavior analytics files (`riskEngine.ts`).
- **`.agents/`**: Folder containing subagent planning documents, heartbeats, and report metadata.

### Build System & Configuration
- **Package Manager / Runner**: Vite acts as the build system and development server.
- **Build Script**: `npm run build` executes `tsc -b && vite build` which compiles the React TypeScript source.
- **Deployment Platform**: Vercel. Route rewrites, HTTP headers (CORS configuration), and cron job paths (executing `/api/cron/crawl` daily at `0 0 * * *`) are defined in `vercel.json`.
- **Linter**: Oxlint (`oxlint` is configured in `package.json` and `.oxlintrc.json`).
- **TypeScript**: Configured using `tsconfig.json`, `tsconfig.app.json`, and `tsconfig.node.json`.

## 2. Threat Feed Ingestion (`api/cron/crawl.ts`)

The cron job `api/cron/crawl.ts` performs parallel fetching and ingestion of threat feeds:

### 1. Ingestion Phase
It fetches threat intelligence from three open-source endpoints:
- **CISA KEV (Known Exploited Vulnerabilities)**:
  - **Source URL**: `https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json`
  - **Parsing**: Fetched via `GET`, parses the JSON object, slices the first 50 vulnerability entries.
  - **Supabase Insertion**: Checks if the `cveID` indicator exists under source `'CISA KEV'` in table `threat_intel`. If not, inserts a record with category `'cve_exploited'`, severity `'critical'`, and description containing vendor, product, and short details.
- **Feodo Tracker C2 Botnet IPs**:
  - **Source URL**: `https://feodotracker.abuse.ch/downloads/ipblocklist.json`
  - **Parsing**: Fetched via `GET`, parses the array, slices the first 50 entries.
  - **Supabase Insertion**: Checks if the IP exists under source `'Feodo Tracker'` in table `threat_intel`. If not, inserts a record with category `'c2_botnet_ip'`, severity `'critical'`, and description including malware family and port.
- **URLhaus Malware Distribution URLs**:
  - **Source URL**: `https://urlhaus-api.abuse.ch/v1/urls/recent/`
  - **Parsing**: Fetched via `POST` with body `'limit=30'`, parses the response, slices the first 30 entries.
  - **Supabase Insertion**: Checks if the URL exists under source `'URLhaus'` in table `threat_intel`. If not, inserts a record with category `'malware_url'`, severity `'high'`, and description listing malware tags.

### 2. Autoencoder Training Phase
Based on the count of newly ingested threat items, a Server-Side Neural Network Autoencoder (`ServerAutoencoder`) is trained to model baseline anomalies:
- Bot samples (gradient ascent) teach the network to maximize reconstruction error on automated, straight, near-zero entropy, fast kinetics.
- Human samples (gradient descent) reinforce the baseline to minimize reconstruction error on natural, curved, higher entropy curves.
- Weights are exported back to the `autoencoder_states` table.

### 3. Threat Level Config Phase
Inserts summary metrics into `threat_feed_stats` and updates the multiplier config in `threat_risk_config` based on the volume of newly saved threat indicators.

## 3. Database Schema (`schema.sql`)

Below is the verified schema for the threat intelligence and statistics tables:

### Table: `threat_intel`
Represents individual Indicators of Compromise (IOCs) ingested by crawler cycles.
- **Columns**:
  - `id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`)
  - `source` (`TEXT NOT NULL`): The feed name (e.g., `'CISA KEV'`, `'Feodo Tracker'`, or `'URLhaus'`).
  - `category` (`TEXT NOT NULL`): Threat type (e.g., `'cve_exploited'`, `'c2_botnet_ip'`, `'malware_url'`).
  - `indicator` (`TEXT NOT NULL`): The actual indicator string (CVE, IP address, or URL).
  - `description` (`TEXT`)
  - `severity` (`TEXT NOT NULL DEFAULT 'medium' CHECK (severity IN ('critical', 'high', 'medium', 'low'))`)
  - `raw_data` (`JSONB`): Stores the raw JSON payload parsed from the feed.
  - `created_at` (`TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL`)
- **Constraints**:
  - Primary key on `id`.
  - Check constraint enforcing allowed severity values (`critical`, `high`, `medium`, `low`).
- **Indexes**:
  - `idx_threat_intel_indicator_source` (Unique index on `(indicator, source)`): Prevents duplication.
  - `idx_threat_intel_category` (B-tree index on `category`)
  - `idx_threat_intel_severity` (B-tree index on `severity`)
- **Row Level Security (RLS)**:
  - Enabled.
  - Policies allow public SELECT and public INSERT.

### Table: `threat_feed_stats`
Logs aggregate metrics for each crawl cycle.
- **Columns**:
  - `id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`)
  - `cves` (`INTEGER DEFAULT 0`): Newly ingested CVEs count.
  - `malicious_urls` (`INTEGER DEFAULT 0`): Newly ingested URLs count.
  - `c2_ips` (`INTEGER DEFAULT 0`): Newly ingested IPs count.
  - `last_updated` (`TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL`)
- **Constraints**:
  - Primary key on `id`.
- **Indexes**:
  - No custom indexes defined in schema.sql.
- **Row Level Security (RLS)**:
  - Enabled.
  - Policies allow public SELECT and public INSERT.

## 4. `/browser` Automation Capability

- **Implementation**:
  - The `/browser` automation capability is provided as a built-in slash command in the Antigravity TUI/CLI and Electron application environment.
  - It runs a virtual headless Chrome instance via local browser integration tools (`open_browser_url`).
- **Invocation**:
  - Invoked during chat sessions or programmatic tasks when looking up external web pages or scraping search content.
- **Windows System Limitation**:
  - In Windows environments, local chrome mode is not supported by the underlying Antigravity tool layer. Attempting to execute browser commands throws the error: `local chrome mode is only supported on Linux`.

## 5. Testing Framework & Utilities

### 1. Existing Test Utilities
There is no third-party JavaScript testing framework (such as Jest or Vitest) declared in `package.json`. Instead, testing and diagnostics are executed using standalone scripts:
- **`scripts/test-bot.js`**:
  - Runs in NodeJS (`node scripts/test-bot.js`).
  - Simulates organic human behavior (curved paths, velocity variance, keystroke cadence variation) and bot profiles (Selenium WebDriver, Headless VM Crawler, Mobile iOS Emulator).
  - Evaluates these mock payloads locally against the reconstructed server verification rules from `riskEngine.ts` and prints detailed trust/risk scores and behavior flags to the terminal.
- **`scripts/threat_crawler.cjs`**:
  - Invoked via `node scripts/threat_crawler.cjs <seed_url> [max_pages] [max_depth]`.
  - Performs recursive HTTP/HTTPS crawls starting from a seed page, cleans CSS/JS tags, writes HTML dumps under `public/intel/`, and reconstructs `public/sitemap.xml`.

### 2. Sandbox Scratch Files
Three scratch scripts exist at the root of the directory for manual endpoint connectivity verification:
- `scratch_test_supabase.js`: Verifies query status and response on the Supabase REST endpoint.
- `scratch_test_cloudflare.js`: Verifies POST requests to Cloudflare AI Vector Search indexes.
- `scratch_test_deploy.js`: Simulates deploy model configuration updates against Vercel endpoint.
